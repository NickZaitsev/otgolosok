# Wikimapia при переисследовании черновиков

Кнопки «Переисследовать» и массового переисследования в `/admin?section=drafts` добавляют к Perplexity поиск Wikimapia. Ручное глубокое исследование тоже использует Wikimapia; обычная подготовка новых мест остаётся прежней.

Один клиент на сервер сериализует API-запросы всех заданий. Он получает 50 ближайших объектов, отбирает до трёх кандидатов по имени и расстоянию до 150 м, затем читает описания через `place.getbyid`. Детальные карточки повторно проходят отбор: удалённые, далёкие, неподходящие по имени и пустые описания исключаются. Ограничения отбора описаны в [пилоте](wikimapia-pilot.md): отсутствие кандидата не доказывает отсутствие объекта в Wikimapia.

Описание API очищается от HTML и сохраняется в источниках с идентификатором `w1`–`w3`, издателем `wikimapia.org` и канонической ссылкой. Короткие описания принимаются; их полезность, соответствие месту и дословные цитаты проверяются общим этапом извлечения фактов. Совпадение имени и координат само по себе не подтверждает объект.

`checkpoint.wikimapiaResearch` сохраняет источники, статус `ok`, `empty` или `failed` и безопасные коды ошибок до извлечения фактов. При частичной ошибке уже полученные описания используются. Повтор с сохранённым checkpoint не делает те же API-запросы; новое переисследование начинает свежий поиск. Ошибки Wikimapia не останавливают Perplexity; отмена всего задания останавливает обе стадии. Дополнительный поиск имеет предел 150 секунд, включая ожидание в очереди клиента.

## Конфигурация и ограничение скорости

`WIKIMAPIA_API_KEY` передаётся backend через `compose.yaml`. Пустое значение использует публичный тестовый ключ `example`, как в пилоте: минимум 31 секунда между запросами. Собственный ключ задаётся только через окружение и уменьшает интервал до 3,1 секунды. Тестовый ключ ограничивает скорость массового переисследования; для регулярных больших партий нужен собственный ключ. Лимит собственного ключа, подтверждённый пользователем: 100 запросов за 5 минут. Интервал 3,1 секунды допускает максимум 97 начал запросов в любом пятиминутном окне одного процесса, включая повторы; отдельный счётчик окна не требуется.

Клиент ограничивает сетевые повторы тремя попытками, учитывает HTTP 429/5xx и `Retry-After`, поддерживает отмену при ожидании, запросе и повторе. API-ключ, сырые сетевые ошибки, фото и комментарии в checkpoint не попадают.

## Проверки

Тесты pipeline покрывают обычное и глубокое переисследование, короткие описания, проверку цитат Wikimapia, повтор с сохранёнными источниками, недоступность API и неподходящие кандидаты. Тест клиента проверяет отмену запроса в очереди; браузерный сценарий проверяет обе подписи источников и запуск переисследования без потери строк таблицы.

Проверено 6 октября 2026: `pnpm check` прошёл, включая 1727 тестов Vitest, 947 backend-тестов, Python-проверки и production-сборку. Браузерный сценарий `e2e/drafts-admin.spec.ts` прошёл в Chromium на уже запущенном dev-сервере (порт 3001); второй `next dev` в том же каталоге блокируется, поэтому использована временная конфигурация Playwright за пределами репозитория.

6 октября 2026 собственный ключ из локального `.env` проверен одним запросом `place.getnearest`: API успешно вернул 50 объектов. Значение ключа не выводилось и не сохранялось в артефактах; уже работающий backend подхватит изменение окружения после перезапуска или пересоздания контейнера. При нескольких процессах с одним ключом их запросы суммируются, поэтому локальная сериализация одного клиента не гарантирует общий лимит.
