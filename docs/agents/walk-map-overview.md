# Прогулки на карте «Рядом»

Кнопка с иконкой маршрута в правом верхнем углу экрана «Рядом» включает слой всех публичных прогулок: каталожных и открытых всем, одобренных редакцией (тот же набор, что в топе). Прогулки рисуются тонким пунктиром одного из шести приглушённых цветов (`--walk-overview-1…6` в `tokens.css`). Цвет выбирается по хешу ключа прогулки и не меняется между визитами. Выбор слоя хранится в `localStorage` (`otgolosok:around:walks:v1`); по умолчанию слой выключен. В режиме создания прогулки слой скрыт.

## API

`GET|HEAD /api/walks/map?west=&south=&east=&north=` (`backend/walk-map.mjs`):
- ровно четыре параметра, десятичные числа до шести знаков, непустая область не шире `WALK_MAP_MAX_SPAN` = 2° по каждой оси, иначе 400; другие методы — 405; без хранилища аккаунтов — 503 `UNAVAILABLE`.
- ответ `{walks:[{kind, id, title, walkingMinutes, distanceM, stopCount, rating, line}], complete}`, порядок — формула топа, не больше `WALK_MAP_LIMIT` = 300. `complete: false` — список обрезан лимитом. `id` — слаг каталога или токен ссылки, как в топе; владельца, ID аккаунта и запусков нет.
- `line` — `[lat, lon]`, упрощённые Дугласом — Пекером с допуском 6 м и округлённые до 5 знаков. На локальной копии прода 2026-10-12: 23 прогулки, 1 507 вершин, 35 КБ без сжатия, 18 мс.
- Попадание в область — пересечение рамки линии с областью, касание края считается.
- Упрощённые линии открытых прогулок хранятся в памяти по `revision` (`listTopCandidates` отдаёт её): снимок декодируется, только если прогулка новая или изменилась. Без кэша запрос декодировал все снимки, на 1 000 прогулок это ~0,5 с блокировки event loop (замер codex). Каталожные прогулки считаются на каждый запрос: их единицы.
- Ответ отдаётся через `sendCacheableJson` ради сжатия и ETag, но nginx оставляет для `/api/` `no-store`: область показывает, куда человек смотрит на карте.

## Клиент

- `walk-overview.ts` — валидация, хранилище на сессию, геометрия. Область запроса — вдвое больше видимой по ширине и высоте (у `viewport.required` уже полшага масштаба, ещё √2 дают ×2), края привязаны наружу к сетке 0,01° и обрезаны регионом `WALK_REGION` (Москва с Новой Москвой и Зеленоградом). Запрос не уходит, пока видимая область лежит внутри загруженной свежей (`WALK_OVERVIEW_TTL_MS` = 10 мин) области. Новая область отменяет запрос покинутой. Полный ответ области удаляет прогулки, которые из неё пропали. Обрезанный (`complete: false`) ничего не удаляет и не считает область загруженной: при приближении внутри неё запрос уйдёт снова, повтор того же вида — нет. Возврат в загруженную область отменяет запрос покинутой и снимает её ошибку.
- `use-walk-overview.ts` — переключатель, видимые линии (буферная область карты), состояние загрузки. Только 503 с кодом `UNAVAILABLE` (нет хранилища аккаунтов) прячет кнопку до перезагрузки; остальные 503, например обслуживание, показывают ошибку с повтором.
- `ExploreMap` рисует линии в панели `walks` (z 402) — под маршрутом прогулки (410) и маркерами. Линии неинтерактивны: тап проверяется в обработчике клика карты с допуском 16 px (`walksAtPoint`), поэтому пересекающиеся прогулки предлагаются все, ближайшая первой. Тап мимо линий работает как раньше: выбор дома.
- Выбранная прогулка рисуется сплошной линией на светлой подложке в панели `walkSelected`, остальные бледнеют. Карта подстраивается под неё целиком (`fitTarget`), иначе маршрут уходит под карточку.
- Линии доступны только касанием, поэтому сразу за кнопкой слоя стоит skip-ссылка «Список прогулок на карте: N». Она видна только в фокусе и открывает список прогулок видимой области, не выбирая ни одной. Проверка раскладки `e2e/support/layout.ts` считает элементы с `clip-path: inset(50%)` невидимыми.
- `WalkOverviewSheet`: одна прогулка — сразу карточка с «Открыть прогулку» (`/walk?catalog=` или `?share=`); несколько — список, выбранный пункт раскрывает кнопку.
