# Оценки мест и пояснения к дизлайкам

В карточке опубликованного места на карте доступны «Нравится» и «Не нравится».
Повторное нажатие снимает оценку, противоположная оценка заменяет её. После
дизлайка открывается форма с теми же тремя причинами, что у улучшений прогулки,
и необязательным комментарием до 1000 символов. Можно отправить только текст.
Закрытие формы сохраняет дизлайк без пояснения; кнопка «Что можно улучшить?»
позволяет вернуться к форме. Замена на лайк или снятие оценки удаляет пояснения.

Причины вынесены в общий компонент `ImprovementFields`. Запросы к прогулкам
остаются отдельными от оценок мест. Оценка относится к OSM ID места, независимо
от прогулки; неопубликованные места и ещё готовящиеся истории её не принимают.

## Хранение и доступ

Таблица `place_feedback` в `auth.sqlite` создаётся при старте. Один голос на
место и аккаунт или гостевой ключ устройства; ключ сохраняется только в виде
хеша. Удаление аккаунта каскадно удаляет его голоса. Оценки гостя сохраняются
на том же устройстве, оценки аккаунта доступны на других устройствах.

`GET/PUT /api/content/places/{osm-id}/feedback/mine` читает/заменяет свой голос.
Тело PUT: `{rating: 1|-1|null, issues: [...], text: "..."}`. Лайк и снятие
оценки принимают только пустые причины и текст. PUT идемпотентен; клиент
повторяет временные ошибки с ограниченным числом попыток. Повтор уже решённого
запроса с теми же данными не открывает его снова, изменение пояснения открывает.

Проверки Origin, CSRF и личности совпадают с отзывами; лимит записей общий с
запросами улучшений прогулки: 20 в час на аккаунт/IP. При отсутствии хранилища
API возвращает 503. При ошибке записи интерфейс сохраняет прежнюю оценку и
текст черновика, показывая сообщение об ошибке.

Комментарии приватные. В существующем разделе админки «Улучшения» кнопка
«Показать оценки мест» загружает очередь дизлайков, включая голоса без пояснений.
Очередь имеет пагинацию по 25 записей, показывает место, причины, текст и дату;
редактор может отметить отдельный запрос решённым. Лайки в очередь не входят.
API очереди: `GET /api/story-admin/place-feedback?limit=&offset=` и
`POST /api/story-admin/place-feedback/resolve` с `{id}`. Доступ только редакции,
данные авторов в ответы не включаются, комментарии отображаются обычным текстом.

## Проверка

Тесты хранилища и HTTP проверяют замену/удаление голосов, изоляцию авторов,
валидацию, лимиты, защиту записи и закрытие запросов. Браузерные сценарии в
`e2e/place-feedback.spec.ts` проверяют форму, комментарий без причин, сохранение
после перезагрузки и ошибки записи. Существующие тесты формы прогулки проверяют,
что общий компонент сохраняет её поведение.

Проверки реализации: линтеры, обе типизации, 1049 тестов Vitest, 738 тестов
backend, 20 Python-тестов и production-сборка прошли. Отдельный браузерный прогон
оценок и фотографий мест: 19/19, включая 320×568, 844×390 и 1440×900; форма
проверена по скриншотам, возврат фокуса после закрытия — отдельным утверждением.

Расширенный прогон вёрстки и фотографий первоначально дал 334/336: два
сценария офлайн-прогулки остановились на ожидании сохранения копии. Отдельный
прогон обнаружил устаревшее исключение `notices` для 568×320: переполнение уже
устранено, а тест требовал его сохранения. Исключение удалено из
`e2e/layout-invariants.spec.ts`; повторная проверка офлайн-прогулки на всех
17 размерах Chromium прошла. Финальный `pnpm check` прошёл полностью.
