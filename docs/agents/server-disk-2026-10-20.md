# Место на сервере и Chromium для TikTok

## Что занимает диск

Срез 20 октября 2026 года до пересборки Shorts: корневой раздел 77 ГиБ,
занято 43 ГиБ (57%), свободно 34 ГиБ. Самые большие категории:

| Категория | Размер | Источник измерения |
| --- | ---: | --- |
| Образы Docker с учётом общих слоёв | 17,18 ГБ | `docker system df` |
| Каталоги сайтов `/srv/sites` | 16 ГиБ | `du -x -h --max-depth=2 /srv/sites` |
| В том числе бэкапы Отголоска | 6,9 ГиБ | `backups/` |
| В том числе данные генератора | 4,2 ГиБ | `generator-data/` |
| В том числе данные Shorts | 1,9 ГиБ | `otgolosok-content/data/` |
| Системные логи | 2,2 ГиБ | `/var/log`, из них journal — 1,9 ГиБ |

Строки «в том числе» входят в размер сайтов. Docker показывает десятичные
гигабайты; `du -h` и `df -h` — двоичные. Размеры отдельных тегов Docker нельзя
складывать: например, два образа Shorts по 2,16 ГБ почти целиком состоят из
общих слоёв. Из 17,18 ГБ образов Docker считает освобождаемыми 1,91 ГБ,
но среди них есть образы для отката других приложений.

В `generator-data/ops-backups` — 1,5 ГиБ, в `maintenance-backups` — 206 МиБ,
в `audio` — 1,8 ГиБ. Два самых больших архива выкладки генератора от
14 октября занимают 2,3 и 2,4 ГиБ. Эти данные и архивы не удалялись.
Для дальнейшей очистки стоит согласовать срок хранения бэкапов и лимит
системного журнала, сохранив проверенные копии для восстановления.

## Почему нельзя удалить весь образ Shorts

Отдельного образа TikTok нет. В `otgolosok-shorts:local` находились полный
Chromium (`/ms-playwright/chromium-1243`, 393 МиБ) и headless shell
(`chromium_headless_shell-1243`, 261 МиБ). Полный браузер использует
TikTok Studio, а headless shell нужен для рендера роликов. TikTok в
серверном `SHORTS_CROSSPOST` выключен.

В соседнем проекте `otgolosok-shorts` Dockerfile переведён на
`playwright install --with-deps --only-shell chromium`; инструкция включения
TikTok обновлена. Для возвращения TikTok потребуется установка полного
Chromium, пересборка и проверка рендера.

Перед серверной сборкой проверено совпадение всех файлов `src/`, `assets/`,
манифестов зависимостей и `tsconfig.json` в работающем образе с каталогом
`app/`. Пересборка использует этот каталог, чтобы сохранить ранее выложенные
исправления. Проверка соседнего проекта `pnpm check` прошла: форматирование,
lint, TypeScript и 1189 тестов в 53 файлах.

## Результат

Новый `otgolosok-shorts:local` (`fa581a5d36b9`) занимает 1,56 ГБ вместо
2,16 ГБ. В контейнере проверены отсутствие полного браузера, наличие headless
shell, одинаковые кадры при повторном переходе к одному времени и отличающиеся
кадры в разные моменты. Штатный renderer создал MP4 длительностью 2 секунды:
1080×1920, 30 кадров/с, H.264, yuv420p, AAC, 48 кГц; `assertShortsSpec` прошёл.
После переключения успешна команда Compose `shorts status --limit 1`.

Удалены старые образы Shorts `8cefc15cf5f1` и
`otgolosok-shorts:before-creative-9377f67` (`f51451cf21da`), затем адресно
удалены 584,8 МБ собственного кэша сборки по ID через `buildx prune --filter`.
Общая очистка Docker не запускалась. Сайт, генератор и Valhalla сохранили
работоспособность; ранее здоровые контейнеры остались `healthy`.
Публичные главная страница и `/api/content/map-cells` вернули HTTP 200
при подключении по HTTP/2. Изменения Dockerfile и инструкции в соседнем
проекте закреплены коммитом `3941bf9`.

Итог: занято 43 ГиБ (57%), доступно 34 ГиБ — 36 049 879 040 байт.
Docker показывает 17,08 ГБ образов, из которых 3,143 ГБ считает освобождаемыми.
Параллельно другая сессия собирала backend генератора; изменение свободного
места всего раздела нельзя приписывать только уменьшению образа Shorts.
Полный `pnpm check` основного проекта также прошёл, включая сборку сайта.

## Скорость сборки и SSH

Загрузка 1 МиБ индекса с `https://deb.debian.org` заняла около 15 секунд
(69 КБ/с), а с `https://mirror.yandex.ru` — 0,12 секунды (8,4 МБ/с).
HTTP основного CDN тоже оказался медленным. Переход на сеть хоста сам по себе
проблему не устранил; успешная сборка выполнена с `--network host` и
`--build-arg DEBIAN_MIRROR=https://mirror.yandex.ru`. В Dockerfile добавлен
выбор зеркала с прежним Debian CDN по умолчанию, таймаут и ограниченные повторы
загрузки пакетов. Проверка подписей Debian не отключалась.

При запуске `docker compose run -T` внутри `ssh … bash -s` нужен
`</dev/null`: иначе Compose может забрать оставшийся текст удалённого
скрипта из stdin, и следующие команды не выполнятся. Удаление образов и
итоговые проверки выполнены отдельным завершившимся скриптом с этим
перенаправлением, под блокировками cron Shorts и YouTube analytics.
