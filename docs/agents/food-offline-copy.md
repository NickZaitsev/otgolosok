# Заведения в офлайн-копии: фаза 6

Реализована только фаза 6 плана `plans/2026-10-04-food-along-walk.md`. Фазы 1–5 уже были закоммичены; новый diff оставлен для ревью без коммита, ветки и выкладки.

## Сверка с актуальным кодом

Подтверждены `walk-packs-v1`, указатель на стадию, `pending.json` и бюджет 60 МиБ; лимиты геометрии WalkDocument — 12 000 вершин и 8 100 м. Подтверждены Shortbread, слой `poi-amenity`, отдельные метки заведений, read-only SQLite и отключение food API ответом 503 при отсутствии индекса. Общий загрузчик уже вынесен в `lib/geo/cell-store.ts`, запросы заведений используют его и отдельный `food-cells-v1`; готового API для засева пакетом раньше не было.

Номера строк фазы 0 устарели, WalkSession теперь включает ящик food, MarkerKind вынесен в `map-marker-look.ts`. `routeLegCuts` выбирает вершины, а проекция на отрезки находится в `food/route-proximity.ts`, как зафиксировано в предыдущих фазах. Импортер адресов по-прежнему использует osmium, `integrity_check` и атомарную замену файла; зависимости opening_hours.js нет.

Есть два пути каталога: универсальная прогулка `/walk?catalog=…` сохраняется через `saveWalkOffline`, а старый TourExperience без WalkView отдельно кеширует опубликованный Route в `published-route-cache.ts`. Для последнего добавлено такое же скачивание заведений, но весь food-снимок принадлежит одному атомарно заменяемому ответу маршрута. Геометрия WalkView — объекты `{lat,lon}`, старого Route — массивы `[lon,lat]`; перед выбором ячеек они преобразуются.

`RTK.md` отсутствует в репозитории; ToolSearch/Ruflo недоступны среди инструментов сессии. Прочитаны план целиком, заметки food-walk-session и food-client-core, руководство установленного Next.js о клиентских компонентах и навык implement-plan.

## Хранение и отказы

- После аудио скачивается валидный манифест и только занятые ячейки из `cellsForRoute(document.route.geometry)`, включая буфер маршрута. Проверяются структура данных, соответствие ячейки ключу, ETag и количество мест; смена версии во время загрузки отменяет весь food-снимок.
- Манифест хранится в `<stage>/food/manifest.json`, ячейки — в `<stage>/food/<lat>/<lon>`. Поле `OfflineWalkManifest.food` необязательно: дата источника, атрибуция и `{key,etag,bytes}` для каждой сохранённой ячейки. Старые пакеты версии 1 остаются читаемыми.
- Размер UTF-8 манифеста и тел ячеек входит в оставшийся после аудио бюджет. Ровно на границе данные сохраняются; при превышении сохраняется только прогулка и аудио. В старом каталоге бюджет заведений также уменьшается на уже кешируемые generated audio.
- Сетевые запросы используют существующие ограниченные повторы с тайм-аутом и экспоненциальной задержкой; 503 повторов не получает. Ошибка ячейки, несогласованный ETag, недостаток места или отказ записи удаляют весь необязательный food-снимок. Прогулка остаётся сохранённой.
- При доступной функции неуспешное сохранение показывает «Заведения не сохранены». При 503, отсутствии геометрии или отсутствии подтверждённого манифеста функции предупреждение не появляется.
- Загрузка пакета валидирует все ячейки до засева foodCellStore. Повреждённая необязательная часть не препятствует открытию прогулки. Засев работает без `food-cells-v1`, не пишет в него и не выдаёт ETag пакета за ETag сетевого манифеста; новая сетевая проверка обновляет данные и условно запрашивает изменившиеся ячейки.
- Ячейки в памяти сохраняют обычную семантику загрузчика. Удаление, выход из аккаунта и обновление удаляют принадлежащие пакету записи Cache Storage вместе со стадией, не затрагивая общие аудиозаписи других пакетов. Старый каталог хранит food внутри ответа маршрута, поэтому отдельные осиротевшие ячейки там не возникают.
