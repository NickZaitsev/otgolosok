# SEO: индексируемые страницы мест, прогулок и районов

Status: фаза 1 реализована в коде, не выложена; фазы 2–4 не начаты

## Зачем

Сайт собран статическим экспортом Next (`next.config.ts`, `output: "export"`): поисковик видит один шаблон, тексты историй приходят из API после загрузки скриптов. Ссылка `/place/<тип>/<номер>` отдаёт только теги превью и скриптом переводит человека на карту (`backend/place-share.mjs`), поэтому робот видит страницу без текста, а человек — другую страницу. sitemap нет. Канонические адреса и hreflang для ru/en/zh уже есть (`src/lib/i18n/root-document.tsx`).

Готовый актив — около 2000 опубликованных рассказов с источниками, фактами, фото с лицензиями и озвучкой. Его нужно сделать видимым для Яндекса и Google, затем строить над ним районные статьи.

## Фаза 1. Страницы мест и sitemap

1. `/place/<тип>/<номер>` рендерит бэкенд полноценной статьёй: заголовок, адрес, фото с автором и лицензией, все абзацы, аудиоплеер `<audio>`, источники, ссылки на соседние места, кнопка «Слушать на карте». Автоматического перехода на карту нет: робот и человек видят одну страницу.
2. Канонический адрес — без `?lang`: текст рассказа один и тот же, `lang` меняет только язык ссылки на карту.
3. Тонкие страницы (меньше 50 слов или служебные тексты `test_placeholder`) отдают `noindex, follow` и не попадают в sitemap.
4. JSON-LD: `Article` с `about` = `TouristAttraction` (координаты, адрес), `audio` = `AudioObject`, `image`, `BreadcrumbList`.
5. `/sitemap.xml` отдаёт бэкенд: главная, `/trends`, все индексируемые места с `lastmod` по дате текста. Nginx проксирует `location = /sitemap.xml`; `robots.txt` получает строку `Sitemap:`.
6. Стили страницы — встроенный `<style>`, разрешённый хешем в CSP; скриптов нет (JSON-LD не исполняется).

После выкладки (делает владелец): подтвердить сайт в Яндекс.Вебмастере и Google Search Console, отправить sitemap.

## Фаза 2. Страницы прогулок

Каталожные прогулки сейчас открываются только по `/walk?id=…`. Нужны адреса вида `/walks/<slug>` с описанием, списком остановок со ссылками на страницы мест, длительностью и кнопкой «Начать прогулку»; включить их в sitemap.

## Фаза 3. Районные статьи (пилот: 3 района)

`/moscow/<район>`: редакторский текст 1200–2000 слов, 6–12 фото с атрибуцией, статичная карта района с точками (интерактивная — по клику), 3–5 встроенных плееров историй, блок мест района со ссылками, кнопка промо-прогулки. Тексты хранятся в репозитории. Перед написанием — частотность запросов в Wordstat. Кандидаты по готовому контенту: Остоженка и Поварская, Замоскворечье (Ордынка, Пятницкая), Китай-город с Зарядьем и Островом. Оценка через 6–8 недель.

## Фаза 4. Видео района

Один ролик на район (60–90 с) через `otgolosok-shorts`, на странице — загрузка по клику, `VideoObject`. Площадки: VK Видео, Rutube, Дзен, YouTube.

## Риски

- Фильтры малополезного контента Яндекса и scaled content abuse Google: районные статьи — живая редактура, не склейка рассказов мест.
- Изменение поведения ссылок «Поделиться»: из мессенджера человек попадает на статью с плеером и кнопкой карты, а не сразу на карту.
- Тяжёлые карта и видео — только по клику, чтобы не ухудшать Core Web Vitals.
