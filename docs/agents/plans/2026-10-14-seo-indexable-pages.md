# SEO: индексируемые страницы мест, прогулок и районов

Status: фаза 1 реализована в коде, не выложена; фазы 2–4 не начаты

## Зачем

Сайт собран статическим экспортом Next (`next.config.ts`, `output: "export"`): в исходном HTML один шаблон, тексты историй приходят из API после загрузки скриптов. Роботы Яндекса и Google умеют выполнять JavaScript, но содержательной посадочной страницы у места не было: `/place/<тип>/<номер>` отдавала только теги превью и скриптом уводила на карту (`backend/place-share.mjs`). sitemap не было. Канонические адреса для ru/en/zh есть (`src/lib/i18n/root-document.tsx`), но `hreflang` в экспорте относительные (`href="/en"`), а Google требует абсолютные URL.

Готовый актив — около 2000 опубликованных рассказов с источниками, фактами, фото с лицензиями и озвучкой. Его нужно сделать видимым для Яндекса и Google, затем строить над ним районные статьи.

## Фаза 1. Страницы мест и sitemap

1. `/place/<тип>/<номер>` рендерит бэкенд полноценной статьёй: заголовок, адрес, фото с автором и лицензией, все абзацы, аудиоплеер `<audio>`, источники, ссылки на соседние места, кнопка «Слушать на карте». Автоматического перехода на карту нет: робот и человек видят одну страницу.
2. Канонический адрес — без `?lang`: текст рассказа один и тот же, `lang` меняет только язык ссылки на карту.
3. Тонкие страницы (меньше 50 слов или служебные тексты `test_placeholder`) отдают `noindex, follow` и не попадают в sitemap.
4. JSON-LD: `Article` с `about` = `TouristAttraction` (координаты, адрес), `audio` = `AudioObject`, `image`, `BreadcrumbList`.
5. `/sitemap.xml` отдаёт бэкенд: главная и все индексируемые места, без `lastmod`. Nginx проксирует `location = /sitemap.xml`; `robots.txt` получает строку `Sitemap:`.
6. Стили страницы — встроенный `<style>`, разрешённый хешем в CSP; скриптов нет (JSON-LD не исполняется).

После выкладки (делает владелец): подтвердить сайт в Яндекс.Вебмастере и Google Search Console, отправить sitemap. До выкладки сохранить исходные показатели.

### Доделки фазы 1 (по ревью Codex 14 октября)

- Поля первой публикации и последнего существенного изменения страницы места (текст, фото, аудио): тогда вернуть `datePublished`, `dateModified` и `lastmod`.
- Метрика на страницах мест: сейчас скриптов нет, и вход из поиска, прослушивание и переход на карту в Метрику не попадают — видны только данные Вебмастера. Подключение — существующий счётчик с узким CSP; требует согласования.
- Абсолютные `hreflang` в `siteMetadata` (production `metadataBase`).
- Длина в 50 слов — грубый фильтр, а не оценка качества: перед массовым открытием проверить выборку страниц на ошибки фактов и повторяемость, рассмотреть явный статус SEO-публикации.
- Интеграционная проверка через nginx: итоговые заголовки, медиа через прокси, эффективное правило robots для `/api/place-images/`.

## Фаза 1б. HTML-каталог мест

Sitemap сообщает адреса, но шесть соседей не связывают весь каталог: группам мест нужен обычный путь от главной. Каталог по городам и районам с пагинацией и простыми `<a href>` — до районных статей.

## Фаза 2. Страницы прогулок

Каталожные прогулки сейчас открываются только по `/walk?id=…`. Нужны адреса вида `/walks/<slug>` с описанием, списком остановок со ссылками на страницы мест, длительностью и кнопкой «Начать прогулку»; включить их в sitemap.

## Фаза 3. Районные статьи (пилот: 3 района)

Сначала таблица «кластер запросов → посадочная страница → спрос (Wordstat, регион и сезонность) → выдача Яндекса → готовность материала». История дома ведёт на страницу места, маршрут — на прогулку (длительность, старт, финиш), обзор района — на хаб. Объём статьи определяет задача читателя, 1200–2000 слов — ориентир, а не норма.

`/moscow/<район>`: редакторский текст 1200–2000 слов, 6–12 фото с атрибуцией, статичная карта района с точками (интерактивная — по клику), 3–5 встроенных плееров историй, блок мест района со ссылками, кнопка промо-прогулки. Тексты хранятся в репозитории. Перед написанием — частотность запросов в Wordstat. Кандидаты по готовому контенту: Остоженка и Поварская, Замоскворечье (Ордынка, Пятницкая), Китай-город с Зарядьем и Островом. Оценка через 6–8 недель.

## Фаза 4. Видео района

Один ролик на район (60–90 с) через `otgolosok-shorts` — прежде всего отдельный канал привлечения и улучшение статьи. Плеер, появляющийся только по клику, Google может не найти: для видеоиндексации нужен обнаруживаемый контейнер с постером и `VideoObject`. Площадки выбирать по измеренным переходам и прослушиваниям.

## Риски

- Фильтры малополезного контента Яндекса и scaled content abuse Google: районные статьи — живая редактура, не склейка рассказов мест.
- Изменение поведения ссылок «Поделиться»: из мессенджера человек попадает на статью с плеером и кнопкой карты, а не сразу на карту.
- Тяжёлые карта и видео — только по клику, чтобы не ухудшать Core Web Vitals.
- Разметка schema.org — вспомогательная: особый сниппет она не гарантирует, особенно в Яндексе. Главное — содержание, title, description, ссылки.

## Измерение

Воронка по группам URL: обнаружено → обойдено → в поиске → показы → переходы → прослушивания и старт прогулки. Пилот оценивать после появления страниц в поиске, а не по календарю.
