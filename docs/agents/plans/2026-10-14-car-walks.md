# План: автомобильные прогулки с остановками

Status: implemented 2026-10-14 in branch `main`. Локальная реализация проверена; production-развёртывание не выполнялось.

> План фиксирует состояние кода на дату создания. Перед продолжением проверять факты по текущим файлам; план не заменяет документацию архитектуры.

## Контекст

Исследование: [автомобильные прогулки](../car-walks-research-2026-10-13.md). Пользователь выбрал поездки с остановками, затем поручил реализовать предложенную схему. Пешеходные документы и сценарии должны сохраниться.

## Принятые решения

1. Первая версия: доехать до парковки, пройти одну или несколько историй и вернуться к машине.
2. Предпочтение «Пешком / На машине» на устройстве, отдельный переключатель для новой поездки. Сохранённая прогулка не меняет режим от общей настройки.
3. Автопоездка на 60/120/180 минут общего времени: переезды, ходьба, посещение, запас на парковку. Длительность без пробок приблизительная.
4. Автоподбор требует общедоступной парковки с доступными автомобильным и пешим путями. Ручной выбор парковки с неизвестным доступом требует явного выбора с предупреждением; явно запрещённые парковки исключаются.
5. Valhalla `auto` для переездов и `pedestrian` для пеших участков. Ведение по поворотам передаётся внешним Яндекс Картам до въезда на парковку.
6. Москва и Казань в существующих границах. Загородные поездки и рассказы при проезде мимо объектов отдельно.

## Факты кода

- `backend/walk-document.mjs` — общий строгий контракт v2. Расширение `travelMode` и `route.car` сохраняет старые документы; поля автомобильной поездки проверяются отдельно и запрещены для ходьбы.
- `backend/walks.mjs` — существующий пешеходный планировщик; автомобильный выносится в `backend/car-walks.mjs`, сервер выбирает его по режиму.
- `backend/content-store.mjs:listWalkCandidates` — текущий радиус до 5 км, для автомобильного запроса нужен ограниченный больший радиус без изменений обычного вызова.
- `scripts/build-osm-food-index.py` и `backend/food-places.mjs` — образец локального индекса SQLite с манифестом и ячейками. Исходный объединённый PBF уже есть в `artifacts/kazan-osm/moscow-kazan.osm.pbf`.
- Адаптеры явно перечисляют поля: `src/features/walks/adapters.ts`, `backend/walk-plan-document.mjs`. Хранилища сохраняют полный проверенный документ.
- `src/features/tour/walk-direction.ts`, `backend/walk-entry.mjs`, `src/features/walks/food-stop.ts` используют одну пешеходную линию; нужны защиты для автомобильных документов.

## Реализация

1. Общий `backend/car-route.mjs`: типы парковок, визитов и участков, валидация ссылок на стабильные ID историй, длительности и геометрии. Расширить общий контракт v2, модели и адаптеры без изменения смысла `walkingMinutes`.
2. Импорт парковок из OSM в отдельный атомарно заменяемый SQLite. Отличать маркер, въезд, выезд и пеший доступ; неизвестность не превращать в разрешение или бесплатную стоянку. Добавить публичные API ячеек и ближайших парковок с ограниченными ответами.
3. Автопланировщик: ограниченный поиск кандидатов, группировка историй у парковки, фактические дорожные маршруты туда и назад, общий бюджет, ограниченные повторы временных ошибок и отсутствие прямолинейного fallback.
4. Настройки, форма и карта: предпочтение только для новых черновиков, автомобильное время, ручной выбор парковки, загрузка слоя по видимой области. Разные стили автомобильных и пеших участков, выбранная парковка всегда видна в маршруте.
5. Отдельный `DrivingExperience`: переезд → посещение → возврат → следующая парковка. Во время переезда и возвращения нет автоматического рассказа. Сохранение/офлайн используют существующий WalkView; ссылки на навигатор строятся только из проверенных координат.
6. Библиотека и каталог используют общее время для машин и маркируют режим. Не предлагать автомобильные маршруты как пешеходный вход в середине. Запретить переворот автомобильной геометрии и пешеходную вставку кафе до реализации соответствующего смешанного расчёта.

## Проверки

Контракт и адаптеры: старый документ, автомобильный длиннее 8,1 км, несколько историй у парковки, битые ссылки, неправильные суммы времени, сохранение и офлайн. Планировщик: разные обратные дороги, недоступная парковка, неизвестный доступ, отсутствие маршрута, общий бюджет и ошибки сервиса; платные API не вызываются в тестах. UI: предпочтение нового черновика, сохранённый режим, навигатор до въезда, запрет аудио в машине, возврат и завершение. Проверить браузером мобильный и большой экран; перед коммитом `npm run check` и целевые E2E.

## За рамками

Живые свободные места, точные тарифы, пробки, встроенное ведение по поворотам, загородное покрытие, импорт парковочных полос на дорожных линиях и автоматическое преобразование опубликованных пешеходных прогулок.

## Фактическая реализация и ограничения

Автоподбор использует опубликованные истории в радиусе 25 км, до восьми парковочных визитов и до трёх историй на визит. Ручной маршрут сохраняет порядок, включая повторный визит на парковку. Общий лимит включает рассчитанные переезды и ходьбу, пять минут на историю и пять минут на парковку; маршрут может оказаться короче выбранного времени.

OSM-импорт включает наземные парковки с найденным въездом или внутренней подъездной дорогой. Одна найденная точка пока служит въездом, выездом и пешим доступом: отдельные роли представлены контрактом, но импорт не устанавливает их независимо. Недоступные фактические дорожные/пешие пути отклоняются маршрутизатором. Подземные парковки и парковочные полосы исключены.

Локальный индекс собран: 3712 парковок, 1487 с общественным доступом, 2225 с неизвестным; 136 ячеек. Сборка и проверка описаны в [заметке реализации](../car-walks-implementation-2026-10-14.md). Для production требуется собрать `osm-parking.sqlite` в каталоге данных генератора и перезапустить backend; отсутствие индекса возвращает 503. Навигация по поворотам требует внешнего приложения и сети.
