# Интерфейс для нескольких городов

13 октября 2026 года пользователь решил показать Казань всем, а не только по общим ссылкам. Город определяется по геопозиции, его можно переключить вручную. Создавать истории о выбранном доме по-прежнему можно только в Москве.

## Как устроено

- Реестр городов — `backend/cities.json` и `backend/cities.mjs`. Фронтенд читает его через `src/features/city/current-city.ts`: город по точке, сохранённый выбор (`localStorage`, ключ `otgolosok:city:v1`) и хук `useCurrentCity`. Без доступа к хранилищу выбор держится до перезагрузки страницы.
- Статическая страница отрисовывается с Москвой. Хук возвращает третьим значением признак, что выбор уже прочитан. Пока его нет, «Тренды» ничего не запрашивают: иначе после гидратации успевает уйти запрос московского топа, и e2e это поймал.
- Карта без сохранённого вида открывается на текущем городе. Геопозиция внутри города запоминает его. Вне каталога сообщение предлагает города кнопками: выбор запоминается и переносит карту.
- Слой «Прогулки на карте» грузит прогулки в пределах `region` того города, в котором центр вида. Если центр вне городов, запросов нет: одна рамка не может охватить и Москву, и Казань (сервер ограничивает её 2° по каждой оси).
- `/api/top-walks?city=moscow|kazan`. Без параметра сервер отдаёт Москву, поэтому старые клиенты и кэшированные URL работают как раньше; фронтенд параметр для Москвы не передаёт. Город прогулки берётся из поля `city` документа, если его нет — по точке старта. Места в рейтинге считаются внутри города.
- Метро: `backend/metro-stations.json` (Москва, `api.hh.ru/metro/1`) и `backend/metro-stations-kazan.json` (одна линия, 11 станций, `api.hh.ru/metro/88`, снимок 13.10.2026). Пункт «Внутри Кольцевой» есть только у Москвы. Названия станций взяты из API как есть, например «Кремлевская» через «е».

## Что осталось московским

- Выбор дома и подготовка истории: `isMoscowPoint` в `around-screen.tsx`. Для казанской точки показывается отдельное сообщение: здесь пока только готовые прогулки.
- Конструктор прогулок, геокодер `places.mjs`, предложение прогулок рядом в конструкторе (`use-nearby-walks.ts`).
- Часовой пояс промоочереди и счётчиков запусков: у Казани он тот же (UTC+3).

## Проверки

- Тест API `walk-top-api.test.mjs`: каждый город видит только свои прогулки и своё метро, ошибочный `city` даёт 400.
- Юнит-тесты модуля города и переключателя в «Трендах», e2e `geolocation-control.spec.ts`: Петербург → выбор Казани → «Тренды» с `city=kazan`; геопозиция в Казани запоминает город.
- Полный e2e в Chromium: 30 падений и на чистом `main`. Это устаревшие тесты, которые ищут удалённые кнопки масштаба «Приблизить» и «Отдалить» (`interface`, `around-food`, `i18n`, `map-catalog` и др.), их нужно обновить отдельно. Тест свайпа в `walk-session.spec.ts:270` нестабилен и проходит при повторе. При параллельном запуске трёх браузеров (`pnpm exec playwright test`) падают сотни тестов по таймауту; сравнивать результаты надо по одному проекту.
