# Интерфейс для нескольких городов

13 октября 2026 года пользователь решил показать Казань всем, а не только по общим ссылкам. Город определяется по геопозиции, его можно переключить вручную. Создавать истории о выбранном доме по-прежнему можно только в Москве.

## Как устроено

- Реестр городов — `backend/cities.json` и `backend/cities.mjs`. Фронтенд читает его через `src/features/city/current-city.ts`: город по точке, сохранённый выбор (`localStorage`, ключ `otgolosok:city:v1`) и хук `useCurrentCity`. Без доступа к хранилищу выбор держится до перезагрузки страницы.
- Статическая страница отрисовывается с Москвой. Хук возвращает третьим значением признак, что выбор уже прочитан. Пока его нет, «Тренды» ничего не запрашивают: иначе после гидратации успевает уйти запрос московского топа, и e2e это поймал.
- Карта без сохранённого вида открывается на текущем городе. Геопозиция внутри города запоминает его. Вне каталога сообщение предлагает города кнопками: выбор запоминается и переносит карту.
- Слой «Прогулки на карте» грузит прогулки в пределах `region` того города, в котором центр вида. Если центр вне городов, запросов нет: одна рамка не может охватить и Москву, и Казань (сервер ограничивает её 2° по каждой оси).
- `/api/top-walks?city=moscow|kazan`. Без параметра сервер отдаёт Москву, поэтому старые клиенты и кэшированные URL работают как раньше; фронтенд параметр для Москвы не передаёт. Город прогулки берётся из поля `city` документа, если его нет — по точке старта. Места в рейтинге считаются внутри города.
- Метро: `backend/metro-stations.json` (Москва, `api.hh.ru/metro/1`) и `backend/metro-stations-kazan.json` (одна линия, 11 станций). Названия и линия Казани взяты из `api.hh.ru/metro/88`, а координаты — из узлов станций OpenStreetMap (выгрузка 2026-10-11). У hh.ru «Авиастроительная» стояла почти на месте «Яшьлек», в 3 км от станции, поэтому прогулки у неё получали «Северный вокзал». Остальные станции у hh.ru расходятся с OSM на 23–249 м. «Кремлёвская» записана через «ё». Пункт «Внутри Кольцевой» есть только у Москвы.

## Что осталось московским

- Выбор дома и подготовка истории: `isMoscowPoint` в `around-screen.tsx`. Для казанской точки показывается отдельное сообщение: здесь пока только готовые прогулки.
- Конструктор прогулок, геокодер `places.mjs`, предложение прогулок рядом в конструкторе (`use-nearby-walks.ts`).
- Часовой пояс промоочереди и счётчиков запусков: у Казани он тот же (UTC+3).

## Проверки

- Тест API `walk-top-api.test.mjs`: каждый город видит только свои прогулки и своё метро, ошибочный `city` даёт 400.
- Юнит-тесты модуля города и переключателя в «Трендах», e2e `geolocation-control.spec.ts`: Петербург → выбор Казани → «Тренды» с `city=kazan`; геопозиция в Казани запоминает город.
- Полный e2e в Chromium: 30 падений и на чистом `main`. Это устаревшие тесты, которые ищут удалённые кнопки масштаба «Приблизить» и «Отдалить» (`interface`, `around-food`, `i18n`, `map-catalog` и др.), их нужно обновить отдельно. Тест свайпа в `walk-session.spec.ts:270` нестабилен и проходит при повторе. При параллельном запуске трёх браузеров (`pnpm exec playwright test`) падают сотни тестов по таймауту; сравнивать результаты надо по одному проекту.

## Выпуск 13 октября

- Генератор и статика выложены с `ea7213c` после того, как на проде опустела чужая очередь озвучки (194 задания, около 115 в час): деплой генератора перезапускает сервис и прервал бы её.
- K01–K04 переведены из `shared` в `public` с одобрением для топа через `setWalkVisibility(..., { autoApprove: true })` служебного аккаунта `promo-walks`; общие ссылки не изменились. Перед операцией снята копия базы аккаунтов с `PRAGMA integrity_check`, остальные 29 одобренных прогулок не затронуты.
- `account-store` сам открывает `BEGIN IMMEDIATE` на каждый вызов, поэтому внешняя транзакция вокруг нескольких вызовов падает; операцию делать идемпотентной, по одной прогулке.
- После выпуска `/api/top-walks?city=kazan` отдаёт четыре прогулки со станциями «Кремлёвская» (до 14.10 — «Кремлевская») и «Площадь Тукая», московский топ остался из 29 прогулок без казанских. В мобильном Chromium «Тренды» переключаются на Казань, а главная карта после выбора открывается на Казанском кремле.

## Ревью Codex (gpt-6.1-sol), 14 октября

Первый запуск упёрся в лимит ChatGPT, но в журнале остались два воспроизведённых дефекта, полный отчёт дал повторный запуск. Все находки подтверждены по коду и исправлены с тестами, которые падали до исправления:

- Выбор города, который не удалось записать в `localStorage`, проигрывал прежнему сохранённому значению.
- «Тренды» не сбрасывали фильтры метро и показанный список при смене города в другой вкладке: уходил запрос Казани с московской станцией, московский список оставался и догружался. Сброс теперь происходит при любой смене города.
- Добавление заведения в казанскую прогулку отклоняло корректный путь: `isPlan` конструктора проверял точки через `isMoscowPoint`. Появились `isPlaceIn`/`isPlanIn` с проверкой по городу самой прогулки. Новый параметр в `isPlace` добавлять нельзя: она передаётся в `.every(isPlace)`, и вторым аргументом придёт индекс.
- Карточка казанской истории вела в московский конструктор («Выберите адрес в Москве»). Ссылка теперь только для Москвы.
- У hh.ru координаты «Авиастроительной» были почти координатами «Яшьлек»; справочник переведён на координаты OSM.
- Сохранённый вид карты перекрывал выбранный город после «Трендов». Вид другого города теперь уступает центру выбранного (`viewSuitsCity`).
- Города в сообщении «вне каталога» были ссылками высотой около 20 px, теперь это кнопки не меньше 44×44.

Осталось: смена города в другой вкладке не двигает уже открытую карту; новый город применится при следующем открытии карты.
