# Запросы на улучшение прогулки

Зритель отмечает, что мешает в прогулке, а редакция видит сводку по прогулкам.
Варианты (можно несколько):

| Код | Текст для зрителя | Колонка в админке |
|---|---|---|
| `short_text` | Мало информации: тексты слишком короткие | Мало информации |
| `no_images` | Нет превью изображений | Нет превью |
| `voiceover` | Не нравится озвучка | Озвучка |

Запрос не публичный, без оценки и без модерации. Принимается для тех же прогулок,
что и отзывы: каталожных, по общей ссылке и своих из аккаунта. Локальные гостевые
прогулки (`?local=`) запросов не принимают.

## Где в интерфейсе

- Экран прогулки: в настройках (кнопка с ползунками) под «Оценить прогулку» —
  «Что улучшить в прогулке?». Работает и до старта, и во время прогулки.
- Экран завершения: та же кнопка над «Оставить отзыв» / «На карту».
- Админка: вкладка «Улучшения» (`/admin?section=improvements`).

Диалог при каждом открытии читает сохранённый запрос: отметки могли измениться на
другом устройстве. Неизменённый открытый запрос отправить нельзя; если снять все
отметки, кнопка становится «Отозвать запрос».

## Данные

Таблица `walk_improvement_requests` лежит в `auth.sqlite`, создаётся в
`backend/walk-improvements.mjs` при старте.

- Цель и автор устроены так же, как у отзывов (см. [`walk-reviews.md`](walk-reviews.md)):
  `walk_kind` + `walk_id` определяет сервер, автор — `user_id` (каскадно удаляется с
  аккаунтом) или `guest_key_hash` от того же ключа устройства `X-Review-Key`.
- Один запрос на пару «прогулка + автор». Причины хранятся флагами
  `issue_short_text`, `issue_no_images`, `issue_voiceover`; хотя бы один обязателен
  (CHECK). `PUT` с пустым списком удаляет запрос.
- Статус `open` → `resolved` ставит редактор сразу для всех открытых запросов
  прогулки. Любая повторная отправка зрителя снова делает запрос `open`: проблема,
  видимо, осталась.

## API

| Метод и путь | Назначение |
|---|---|
| `GET/PUT /api/story-walks/{slug}/improvements/mine` | каталог |
| `GET/PUT /api/story-walks/shared/{token}/improvements/mine` | общая ссылка |
| `GET/PUT /api/me/walks/{id}/improvements/mine` | своя прогулка |
| `GET /api/story-admin/improvements?status=&issue=&q=&limit=&offset=` | сводка по прогулкам |
| `POST /api/story-admin/improvements/resolve` `{kind, id}` | закрыть открытые запросы прогулки |

Тело `PUT` — строго `{ "issues": [...] }`. Публичные записи проходят ту же проверку
Origin/`Sec-Fetch-Site` и CSRF, что отзывы (`backend/walk-feedback.mjs`). Лимит —
20 записей в час на аккаунт или IP, отдельный от лимита отзывов и тоже в памяти
процесса: сбрасывается при рестарте.

Сводка группирует запросы по прогулке и сортирует по числу запросов. Имена и email
авторов в неё не попадают.
