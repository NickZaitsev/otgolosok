## Хранилище

Общая часть загрузчика существенно больше 60 строк: выделена в `src/lib/geo/cell-store.ts`. Доменные валидаторы и публичный API карты остались в `map-cells.ts`; существующие тесты карты не изменены. Сохранены выдача старого кеша сразу, фоновая ревалидация, ETag, объединение запросов, дедупликация мест по id и лимит четыре загрузки.

`createFoodCellStore` предоставляет `loadManifest()`, `loadKeys(keys)` для маршрута, `loadArea(bounds)` для вьюпорта, подписку, стабильный `snapshot()`, `retry()` и `revalidate()`. Данные — `FoodPlace[]`, метаданные — дата источника и атрибуция. Ошибки отражаются в `manifestStatus`/`cellStatus`; пустой массив сам по себе не означает успешную загрузку. `snapshot().unavailable` отличает 503 от обычной ошибки. При наличии кеша ревалидация работает в фоне, поэтому результат проверяется подпиской, а не только завершением `revalidate()`.

Кеш `food-cells-v1` очищает только старые версии food-кеша. Ключ — `floor(coord * 20)` с ограничением +90/+180 последней ячейкой. Формат манифеста и каждой ячейки проверяется целиком; повреждённый кеш заменяется сетевой копией. Ячейки вне манифеста не запрашиваются.

В общий `fetchWithRetry` добавлен необязательный список `noRetryStatuses`; только food-загрузчик передаёт `[503]`. Другие пользователи сохраняют прежнюю политику. Сетевые ошибки, 429 и остальные 5xx: максимум три попытки, паузы 500/1000 мс с существующим jitter; timeout — 20 секунд на попытку, отмена прерывает и запрос, и паузу. Детерминированные 4xx и 503 food API не повторяются автоматически.

## Геометрия и нагрузка

Перед проекциями заведения отсекаются bbox маршрута с буфером. Отрезки индексируются в метровых бакетах; для каждого заведения проверяется только соседство. Длинные отрезки заполняют бакеты вдоль всей линии, дополнительный бакет покрывает пересечения углов сетки. Сортировка — по `alongM`, затем id. В петле выбирается локальный минимум первого прохождения в пределах лучшей дистанции +15 м, но внутри заданного радиуса.

`cellsForRoute` возвращает консервативный набор пересекаемых ячеек с буфером, включая соседей на точных границах. Подписи расстояния округляются до метров, ближайшая остановка выбирается по `alongM`; минуты не обещаются.

Воспроизводимый тест: маршрут 8 100 м / 12 000 вершин, 2 000 заведений; половина в 60 м от линии, половина в 600 м. Bbox отсекает 1 000 мест, остаётся 1 095 290 проверок вместо 23 998 000 наивных пар (4,56%). Тест ограничивает число пар значением менее 10% от наивного объёма, без порога миллисекунд. Дополнительно результаты бакетов сравниваются с полным перебором на извилистой линии.

## Часы работы

Поддержаны `24/7`, дни и списки/диапазоны, включая диапазон через воскресенье; интервалы и перерывы, `24:00`, ночь и Su→Mo; правила через `;`, последнее заменяет выбранные дни; `off`/`closed`; `PH off` игнорируется с `holidayCaveat`. Позднее правило следующего дня заменяет и унаследованный ночной хвост; отмена исходного дня отменяет его хвост. Начало интервала включено, конец исключён.

После замера добавлены простые реальные варианты: час без ведущего нуля, пробел после запятой в списке дней, запятая перед новым правилом с днями, `00:00-00:00` как полные сутки. Другие одинаковые начало/конец остаются неизвестными. Месяцы, недели, sunrise/sunset, комментарии, составные селекторы PH и произвольный текст дают `unknown` для всей строки.

Время вычисляется через `Intl.DateTimeFormat` в `Europe/Moscow`; явный параметр timezone доступен для тестов. `opensAt` содержит `{day,time,daysAhead}`, ближайшее открытие ищется в пределах семи суток. Русские подписи вынесены в `formatHoursStatus`, оговорка о праздниках — в `formatHolidayCaveat`; `unknown` никогда не превращается в «Открыто».

### Замер реального индекса

До реализации парсера быстрый замер обязательной грамматики: 7 411 / 7 685 непустых `opening_hours` (96,43%). После добавления перечисленных простых вариантов реальный `parseOpeningHours`: **7 566 / 7 685 (98,45%)**, неизвестны 119 (1,55%). Индекс открывался только для чтения; строки взвешены по числу заведений, а не уникальным значениям.

Десять самых частых нераспознанных строк (порядок: количество по убыванию, затем строка):

| Строка | Заведения |
|---|---:|
| `Mo-Su,PH 12:00-24:00` | 6 |
| `Mo-Su,PH 10:00-22:00` | 5 |
| `PH,Mo-Su 10:00-23:00` | 5 |
| `PH,Mo-Su 10:00-22:00` | 4 |
| `Mo-Su,PH 11:00-23:00` | 3 |
| `12-00 до 21-00` | 2 |
| `Mo-Su,PH 08:00-22:00` | 2 |
| `Mo-Su,PH 09:00-21:00` | 2 |
| `Mo-Su,PH 09:00-24:00` | 2 |
| `Mo-Su,PH 10:00-23:00` | 2 |

Замер можно повторить через Node с поддержкой TypeScript:

```sh
node --input-type=module <<'JS'
import { DatabaseSync } from 'node:sqlite';
import { parseOpeningHours } from './src/features/food/opening-hours.ts';
const db = new DatabaseSync('backend/data/osm-food.sqlite', { readOnly: true });
try {
  const rows = db.prepare("SELECT opening_hours AS hours,count(*) AS n FROM places WHERE opening_hours IS NOT NULL AND trim(opening_hours)!='' GROUP BY opening_hours ORDER BY n DESC,opening_hours").all();
  const total = rows.reduce((sum, r) => sum + r.n, 0);
  const known = rows.filter(r => parseOpeningHours(r.hours)).reduce((sum, r) => sum + r.n, 0);
  console.log({ total, known, percent: known / total * 100 });
  console.log(rows.filter(r => !parseOpeningHours(r.hours)).slice(0, 10));
} finally { db.close(); }
JS
```

Ограничение: календарь праздников и сложная грамматика не поддержаны. При дальнейшем расширении нужен отдельный согласованный набор правил и тестов, чтобы не выдавать предположение о часах за установленный факт.
