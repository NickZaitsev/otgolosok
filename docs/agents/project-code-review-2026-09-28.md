# Код-ревью проекта — 28 сентября 2026 года

Статус на 28 сентября 2026 года: замечания ниже исправлены по [плану второго ревью](plans/2026-09-28-project-review-hardening.md), кроме явно отмеченных. Первое ревью ([21 сентября](project-code-review-2026-09-21.md)) и его исправления остались в силе; здесь только новые находки.

Проверялась ветка `feat/auth-account-osm-pipeline` после слияния с `origin/main` (`e4cba19`, `94283a0`). Охват: HTTP API и хранилища backend, статический фронтенд с офлайн-режимом, сборка и инструменты репозитория. Платные внешние API при проверке не вызывались.

Исходное состояние на Windows (Node 24.18): lint и typecheck проходили, Vitest — 53 файла / 355 тестов, backend — 272 из 276 (четыре теста `admin-make` требуют `make` и `/bin/sh`), общей команды `pnpm check` не было, Python-скрипты не проверялись.

## Backend

### 1. P1: транзакции Better Auth блокировали данные аккаунта

Better Auth держит `BEGIN … COMMIT` на своём соединении SQLite через `await` (регистрация хеширует пароль внутри транзакции). Account store работал на том же соединении, поэтому запись прогулки или списание квоты в этот момент попадали в чужую транзакцию и откатывались вместе с ней. `BEGIN IMMEDIATE` стоял до `try`, и ошибка начала транзакции оставляла соединение в неопределённом состоянии.

Исправление: отдельное соединение для account store, транзакции через общий помощник (`4014730`). Тест имитирует регистрацию с открытой транзакцией и проверяет, что данные аккаунта сохраняются после её отката.

### 2. P1: общий суточный лимит позволял одному пользователю остановить генерацию для всех

`MAX_DAILY_JOBS` считал задания всего сайта: шесть запросов одного пользователя исчерпывали лимит для остальных. При выключенной авторизации персонального лимита не было вовсе. Устаревший повтор исследования маршрута возвращал уже списанную единицу квоты.

Исправление (`bae1e2d`): остался только персональный лимит `USER_DAILY_GENERATION_LIMIT` (по умолчанию 6 единиц за скользящие сутки); без авторизации платная генерация отвечает 503 `AUTH_REQUIRED`; списание возвращается только тем запросом, который его сделал.

### 3. P2: хранилище аккаунта не имело лимитов

Число прогулок и избранного не ограничивалось; импорт локальных прогулок мог записать любое количество. UUID прогулки из клиентского документа использовался как глобальный первичный ключ, поэтому чужой ID давал конфликт.

Исправление (`4014730`): не больше 200 прогулок и 1000 записей избранного, проверка внутри транзакции, превышение — 409 с сообщением на русском; при совпадении ID с прогулкой другого пользователя выдаётся новый.

### 4. P2: внешние вызовы не повторялись при временных сбоях

Повтор был только в одном методе `provider.mjs`; синтез речи, Yandex TTS и клиент TTS API падали на первом 429/5xx, флаги `transient`/`retryable` никто не читал, `Retry-After` игнорировался. Опрос удалённого синтеза не имел общего срока, а каждое ожидание добавляло слушатель `abort` к сигналу, живущему весь процесс.

Исправление: общий `backend/retry.mjs` с ограниченным экспоненциальным backoff и учётом `Retry-After` (`262a158`); срок опроса TTS и снятие слушателей (`8b83922`).

### 5. P2: остановка сервиса тратила попытки генерации

По SIGTERM задания прерывались как `TIMEOUT` и теряли попытку; активные запросы обрывались; временные файлы `.upload-*` оставались навсегда.

Исправление (`6c40450`): сервер перестаёт принимать запросы, ждёт текущие до `SHUTDOWN_GRACE_MS`, прерванные задания возвращаются в очередь без списания попытки, старые временные файлы удаляются при запуске. В плане предлагался отдельный статус `INTERRUPTED`; возврат в очередь проще и даёт тот же результат.

### 6. P2: тела запросов и кэширование

Обработчик авторизации принимал тело любого размера; локальный nginx разрешал 64 МБ для всего `/api/` и подменял `Cache-Control` у неизменяемого аудио на `no-store`.

Исправление: лимит 16 КиБ для авторизации (`0d0206e`); в nginx 128 КиБ для `/api/`, 64 МБ только для загрузки результата воркера, долгое кэширование аудио с хешем в имени (`38442e4`). Конфигурация nginx не проверена `nginx -t`: Docker на машине разработчика был недоступен.

### 7. P3: построитель маршрутов и выборки воркеров

Второй одновременный запрос маршрута сразу получал `WALK_BUSY`. Выдача задания воркеру разбирала JSON всех заданий в очереди, статистика аудио загружала все строки.

Исправление: очередь ожидания с ограничениями и персональный лимит частоты `WALK_RATE_LIMITED` (`cc4929c`); отбор и агрегаты в SQL (`93cc0b8`).

Пункт о сравнении токена воркера за постоянное время и проверке `profileIds` снят: исправлено в `main` до слияния. Оставшийся `catch`, который только пробрасывал ошибку, удалён (`8f59bf8`).

## Фронтенд

### 8. P1: офлайн-копии работали только для прогулок из аккаунта

Сохранённая копия открывалась без сети только у прогулок из аккаунта; каталог, ссылки и локальные прогулки уходили в сеть и не открывались. Аудио копий лежало вне области пользователя и не удалялось ни при удалении копии, ни при выходе; интерфейса удаления не было. Выход из аккаунта ждал очистки кеша и ломался, если Cache Storage недоступен.

Исправление: копии для всех видов прогулок с отдельными областями хранения, подсчёт ссылок на аудио с учётом кеша опубликованного маршрута, кнопки «Сохранить» / «Обновить» / «Удалить офлайн-копию» (`3ebf28d`); выход не блокируется очисткой и удаляет приватные копии даже при недоступном сервере (`a3ed6e6`). Playwright-тест открывает сохранённую прогулку без сети.

### 9. P2: лишняя работа на главной и во время прослушивания

Каждый заход на главную заново скачивал всё аудио маршрута параллельно, с `cache: "no-store"` и одним общим таймаутом. Каждое событие `timeupdate` пересобирало главы и заново создавало все маркеры карты, сбрасывая фокус клавиатуры.

Исправление: скачиваются только отсутствующие файлы, по одному, со своим таймаутом (`a1cb1a5`); главы мемоизированы, маркеры обновляются по идентификатору (`458cbe7`).

### 10. P2: пользователь видел технические ошибки на английском

`Failed to fetch`, `signal timed out`, ошибки разбора JSON и таймауты попадали в интерфейс как есть. Исправление: `toUserMessage` и замена в 24 местах (`69b8263`).

### 11. P3: прочее

- Service Worker не удалял старые кеши, пока открыта вкладка, а сценарий обновления всегда держит её открытой (`a575c09`).
- Панель диагностики с английскими подписями показывалась всем; теперь только с `?replay=` или `?debug=1`, подписи и сообщения геолокации на русском (`c569585`).
- Доступность: у карты и индикатора геопозиции не было ролей, ссылка «на главную» вела на `#top` (`a840e5f`).
- Мёртвый код и утечки подписок (`0d4e7bf`, `291c31c`); экран прогулки разделён на хуки и компоненты (`0e81e38`).

## Открытые замечания

Найдены при включении `checkJs`, не исправлялись:

- `backend/text-normalizer.mjs` передаёт Python путь к скрипту как `URL.pathname`: на Windows получится `/C:/…`, а пробелы и кириллица останутся в `%`-кодировке. Нужен `fileURLToPath`; на сервере с Linux-путём без спецсимволов работает.
- `backend/store.mjs` в `close()` вызывает `statement.finalize?.()`, но у `StatementSync` в Node 24 такого метода нет — цикл ничего не делает.
- `backend/source-text.mjs` передаёт pdfjs `disableWorker`, который pdfjs-dist 5 не читает; в Node он и так работает без воркера.
- Маршруты `/api/me/*` передают параметры страницы через `...Object.values(accountQuery())`, завися от порядка ключей объекта; надёжнее явная деструктуризация.
- `GET /api/me/walks/:id` отвечает английским `Walk not found.`, соседние маршруты — по-русски.
