# Яндекс.Метрика

Счётчик `113326536` подключён в корневом layout и запускается после гидратации
только в production-сборке. Включены настройки из кода владельца: Вебвизор,
карта кликов, отслеживание ссылок, точный показатель отказов и `dataLayer`.
Само подключение `dataLayer` не создаёт события электронной торговли.

Для App Router используется `defer: true`: начальный просмотр и последующие
изменения пути или query отправляются через `hit`. Повтор эффекта React не
дублирует просмотр. Первый referer берётся из `document.referrer`, дальнейшие —
из предыдущего просмотра. Для выключенного JavaScript добавлен `noscript`.

Загрузчик делает максимум три попытки, интервалы повторов — 1 и 2 секунды;
тайм-аут попытки — 15 секунд. После отказа очередь очищается, дальнейшие
просмотры этой вкладки не накапливаются. Ошибки аналитики не прерывают приложение.

## CSP и выкладка

`scripts/content-security-policy.mjs` разрешает точные адреса коллекторов Яндекса,
региональные домены и Вебвизор; wildcard и `unsafe-eval` не добавлены. Хеши
inline-скриптов Next.js сохраняются. Список взят из
[документации Яндекса](https://yandex.ru/support/metrica/ru/code/install-counter-csp).
Учёт SPA соответствует [инструкции Яндекса](https://yandex.ru/support/metrica/ru/code/counter-spa-setup).

В локальном Docker `docker/security-headers.conf` разрешает встраивание только
интерфейсам Метрики из официального списка, вместо `frame-ancestors 'none'` и
`X-Frame-Options: DENY`. На production заголовки задаёт **другой репозиторий**:
`/Users/fenix007/projects/utils/services/deploy-scripts/deploy-static.sh`.
Перед выкладкой нужно перенести список `frame-ancestors` из Docker-конфига в
Traefik middleware сайта и отключить `frameDeny`. Не менять настройки остальных
сайтов общего deploy-скрипта. Без этого просмотры отправляются, но интерфейс
Вебвизора не сможет встроить сайт для воспроизведения.

После выкладки проверить реальные запросы `mc.yandex.ru/watch/113326536`,
переходы без перезагрузки и просмотр записи в аккаунте владельца Метрики.
Локальные проверки используют подмену стороннего скрипта, чтобы не загрязнять
реальную статистику тестовыми визитами.

## Проверка типов

В ходе подключения полный `pnpm check` обнаружил старую копию исходников
`artifacts/boulevard-walk/release` с импортом уже удалённого модуля. Каталог
`artifacts` исключён из `tsconfig.json`: это игнорируемые результаты работы,
а не исходники приложения. По той же причине `backend/data` исключён из
`tsconfig.backend.json`: локальный скрипт сбора данных использует браузерный
`document`, который не относится к окружению backend.

Тест детерминированного каталога также выявил CRLF в локальном
`backend/builtin-routes.mjs`. Штатная генерация восстановила LF без изменения
данных; для этого генерируемого файла закреплён `eol=lf` в `.gitattributes`,
чтобы checkout с `core.autocrlf` не ломал сравнение с генератором.

`pnpm check` прошёл: lint, проверки типов frontend/backend, 962 теста Vitest,

## Страницы мест

Страницы `/place/<тип>/<номер>` рисует бэкенд, React-счётчик на них не работает. С 14 октября 2026 года у них свой встроенный скрипт `backend/place-metrika.mjs` с теми же правилами: он запускается только при сохранённом согласии на аналитику (ключ, версия, срок 180 дней и формат квитанции — как в `cookieChoice`), отправляет путь без query, без заголовка, без Вебвизора и карты кликов. Реферер обрезается до origin (`https://yandex.ru/`): этого хватает, чтобы отличить поиск, а чужие поисковые запросы не передаются. Загрузка `tag.js` повторяется дважды, с паузами 1 и 2 секунды. Скрипт выводится, только если опубликованы юридические документы (`LEGAL_READY`).

Цели (JavaScript-события, их нужно создать в интерфейсе Метрики): `place_audio_play` — первое воспроизведение записи, `place_audio_end` — запись дослушана, `place_open_map` — переход на карту.

Баннера согласия на странице места нет. Поэтому новый посетитель из поиска не учитывается, пока не даст согласие в приложении; полную статистику поискового трафика дают Вебмастер и Search Console. Контрактный тест `src/features/analytics/place-metrika-contract.test.ts` сверяет ключ, версию и срок согласия, номер счётчика и коллекторы CSP с кодом сайта. Поведение скрипта (отказ, устаревшее и будущее согласие, поддельная квитанция, заблокированное хранилище, цели, повторы загрузки) проверяет `backend/place-metrika.test.mjs` в `node:vm`. В Chromium с настоящим CSP и подменённым `tag.js` проверено: без согласия запросов к Яндексу нет, после согласия загружается `tag.js?id=113326536`, нарушений CSP нет.
